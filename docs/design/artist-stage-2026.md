# Ricorrenza artist stage

The artist section sits immediately after `HomeHero`, before Rico Stars. It follows the supplied emerald and gold reference: the hooded figure, gold wordmark, concert truss, crowd, circular carousel navigation and festival information strip. There is **one active artist screen**. Its smaller side portraits preview the previous and next artist in the carousel. The tilted record-sleeve card contains a vinyl, YouTube watch link, direct social icons and its own About/Listen actions. About opens the full artist details dialog. The main scene scales to 2560px and uses container queries for phone and embedded admin previews.

The active screen shows an artist photo first, then interleaves muted clips with photos. Photos last 3.8 seconds; clips finish naturally or advance at their 30/60-second limit. There are no player controls over the stage media. A separate Pause motion action freezes the presentation and lighting. Reduced motion keeps a still photo. Failed or blocked videos fall back to the artist photo and the sequence continues. Desktop photo/clip uploads are selected at widths above 700px, with phone media as fallback. Visibility changes and open details suspend the main screen.

On phones the 74%-wide active card has a rounded gold/emerald rim, a tilted gold backing and a vinyl record visible behind its right edge. Mobile photo covers use 6:5 while short-clip presentations retain 9:16. The artist name, genre, biography excerpt, social icons and About/Listen controls sit inside the sleeve. Adjacent cards share its height and use blur/dimming for depth. There is no duplicate biography/social/action row below the main card. The information strip contains only the editable festival date and venue. The public year tabs come from the admin’s explicit selection; before configuration, only the current year and years with published profiles are offered. An unannounced edition has one coming-soon screen and access to past years.

Band thumbnails preserve group framing. A saved Spotify artist, playlist, album or track URL provides the official embed. The Spotify social profile is the fallback when the dedicated player URL is empty. ## Admin

Open `/admin/guest-artists` (Artists within the homepage workspace).

- **Stage display settings:** choose visible festival years (including custom years), edit the date/place labels, enable original-lamp colour cycling and uploaded-song beat response. These settings use existing homepage writes/approval handling.
- **Artist details:** performer type (Artist/Band/DJ), name, description, genre, highlights, festival year, display order and visibility.
- **Photos & media:** portrait, photo-slideshow/short-clips choice, up to three phone covers (6:5 or 9:16 with clips), portrait 9:16 clips and independent wide desktop media, 30/60-second clip limit, performer light colour, optional motion poster, performance video/YouTube URL, uploaded/direct audio and song title.
- **Performance:** optional date, time and venue.
- **Social links:** Instagram, YouTube channel, Spotify profile/player URL and optional titled song links.
- **Preview stage:** sample or saved lineup without publishing sample records.

The roster supports edition/visibility filters, performer-type badges and media readiness. Existing approval requirements, upload locks, failed-save draft recovery and visibility/edit/delete flows remain in use. The required band profile photo uses wide group framing; dedicated phone media crops use 9:16 and desktop media crops use 16:9. Photo and clip drafts survive switching media modes. Gallery and clip uploads preserve existing media while editing. The storage garbage collector scans individual URLs in all four phone/desktop image and clip arrays, and aborts deletion if either reference query fails.

## Original stage lights

The colour effect duplicates the existing stage artwork and masks only the original amber lamp fixtures and their glow. It does not add light cones, painted bars or new light sources. The mask uses the original 1672×941 coordinates and shares the backdrop’s desktop/mobile sizing and top alignment. A slow hue cycle runs while no owned song is playing. During uploaded-song playback, that timer is disabled: bass onsets change lamp colour, and a fast attack/135ms decay envelope drives visible brightness pulses. FFT bins are chosen in Hz for the device sample rate, with lower analysis smoothing and separate silence detection. The frame queue uses AudioContext output timestamps (or reported output latency) to align analysis with speaker playback; the analysis loop stops on pause, end, hidden page and cleanup. Audio graphs reuse their source and keep a passthrough when analysis is disabled. Spotify/YouTube iframe audio is not analysed; those players retain ambient lighting. Reduced motion disables the animated lamp layer.

The audio-sync regression suite includes frequency/RMS frames derived from the actual original 16-second demo recording, verifying that the response follows its half-second drum attacks. It also checks held notes, silence, sample-rate changes, output-delay compensation and pause cleanup. Safari diagnostics confirmed live audio signal, advancing beat counts and zero signal/pulse after pause. Optional `audioDebug=1` is available only in the standalone development preview; it is excluded from the production entry.
